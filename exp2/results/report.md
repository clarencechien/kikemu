# 晶晶體(中英夾雜)聽譯評測報告 — exp2

> 回答 handoff-v2:同一個詞表機制在中英夾雜技術演講上是否有效?
> 投影片詞表 vs 領域詞表?哪些英文不該翻?

## 0. TL;DR

**在中英夾雜場景,槓桿不是詞表,是語言 pack。** 這與 kikemu v1(日文專名場景,
詞表 +0.12~0.19)形成完整互補:**詞表的價值取決於缺的是什麼** ——
引擎不認識的在地專名,詞表大補;引擎本來就認識的通用英文術語,詞表近乎零效。

- **換用中英雙語 pack(cmn_en)**:術語召回 +0.23~+0.29(乾淨~辦公室噪音),
  是全實驗最大的單一效果。單語 cmn 把 COVID-19 聽成「CoffeeNight」、
  network 聽成「news」—— 失敗集中在 F2(誤認成別的英文),不是預期的 F1 中文化
- **會前準備(投影片詞表)的邊際價值:+0.03~+0.05**,CI 下緣貼 0 —— 有,但小;
  **領域通用詞表:≈ 0**(-0.01~+0.02)。詞表也救不了錯誤的語言模式
  (cmn+投影片詞表 +0.06~0.09,遠small於換 pack 的 +0.23~0.29)
- **「不該翻」規則(P1)是免費的但也是多餘的**:kikemu 原版 prompt 下
  Transformer/GAN/ChatGPT 被翻成中文的比例已是 0%
- **G(Gemini Live 一體式)乾淨條件最強(0.927)但重演 v1 崩潰**:
  12dB 會議交談下掉到 0.396、TER 0.83 —— 「有人聲背景就不能用一體式」
  在第二個場景複驗成立
- 詞表對延遲零影響(partial p50 ~0.8s、final ~2.3s,三種詞表設定相同)

**一句話建議(廠區/會議線):Speechmatics cmn_en 雙語 pack + kikemu 原版
翻譯 prompt 即為正解;會前投影片詞表是小加分(+3~5pp)可作為進階選項;
會議室有多人交談時不可切換到一體式模型。**

## 1. 方法與信度控制

### 1.1 語料

台大李宏毅課程 3 段 × 5 分鐘(主題不重疊):

| 段 | 課程 | 內容 | 切片 |
|---|---|---|---|
| S1 | ML2021 自注意力機制(上) | Self-attention 導入(drug discovery、graph、one-hot) | 6:00–11:00 |
| S2 | ML2021 GAN(一) | network/distribution/generator(含輝夜動畫離題段) | 7:00–12:00 |
| S3 | 生成式AI導論2024 第1講 | ChatGPT/Transformer/Stable Diffusion | 15:00–20:00 |

- 投影片:`speech.ee.ntu.edu.tw` 官方 PDF 直接下載(self_v7 / gan_v10 / 0223_intro_gai)
- 音訊:YouTube 官方影片在本環境被 bot 驗證擋下,改經公開鏡像取得**同一錄影**
  (S1 時長 1698s 與官方上傳完全一致,逐檔驗證);音檔僅私下評測、不入庫不散布
- S3 切片位置是在任何 arm 執行前,以術語密度探測(300-600s 段僅 8 個英文串,
  900-1200s 段 13 個)後決定的
- 授權注意:課程公開 ≠ 開放授權,報告僅引用短句

### 1.2 標準答案(無官方文字可對照,人工核對比重最高的一步)

- 三路獨立轉寫:Speechmatics batch(cmn)、gemini-3.5-flash、gemini-3.6-flash
- **合併規則(寫死於 build_reference.py):以兩個 Gemini 的 token 級一致部分為基底**;
  80 個分歧塊逐條人工檢視(`corpus/reference/review.md`),裁決寫入 `overrides.json`
- **SM-cmn 不參與英文拼寫的表決**(記錄在案的偏離):它在受測維度上系統性弱勢
  (COVID-19 → 「CoffeeNight」、network → 「news」),讓它投票會污染正解;
  但它的**中文**是可靠的第三意見,用於裁決中文區域:
  - 「英年早逝」「火影忍者」「爆雷」——三方證據一致後修正
  - **關鍵裁決:講者說的是「函式」不是 "function"**(gm35 把 10 處中文「函式」
    英文化成 function;SM 聽到 8 次 函式/函数 佐證)——這同時暴露了
    「用 LLM 做逐字稿會被它的正字法偏好污染」這個方法論陷阱
- 數字讀法(one-hot 向量「1 0 0 0」)按實際唸法修正

### 1.3 術語清單(主要指標正解,凍結)

從已驗證逐字稿機械抽取**實際講出來的**英文串(連續拉丁 token),
排除純填充詞(know, so, ok)與數學式唸法(f x、ax b):

- S1:26 個術語 51 次(label×9, graph×6, saw×4, sentiment analysis×3…)
- S2:10 個 20 次(network×5, distribution×3, model×3…)
- S3:6 個 16 次(ChatGPT×8, AI×3, Transformer×2, Stable Diffusion, Midjourney, DALL-E)

判定規則:strict = 大小寫不敏感完全相符;tolerant = 另接受連字號/空白折疊與
凍結變體(covid 19/covid、one hot、chat gpt…)。變體在任何 arm 執行前凍結。
每個術語標注 no_translate(架構名/專名/縮寫)或 may_translate(一般技術詞),
分類規則機械化 + 凍結手表。

### 1.4 詞表來源(本實驗核心變因)

| 詞表 | 來源 | 條數 | 洩漏控制 |
|---|---|---|---|
| domain | Google ML Glossary 公開頁(765 詞目→645 條) | 645 | **絕不接觸投影片與逐字稿** |
| slides_S1/S2/S3 | 該堂課官方投影片 PDF 文字 → Gemini 抽取 | 42/81/22 | 與逐字稿高度重疊是產品場景,非洩漏 |

### 1.5 聲學條件 M0-M3

- RIR:MIT IR Survey,**規則 = Classroom 空間中 T60 最接近 0.8s** →
  `h100_Classroom`(T60=0.721s)。(無限制的最接近值是浴室 —— 衰減對、空間錯,
  規則因此加上空間類別約束,並記錄)
- M2 = M1 + DEMAND OOFFICE(辦公室實錄)@ SNR 20dB;M3 = M1 + DEMAND
  OMEETING(會議交談實錄)@ SNR 12dB;語音活動段 RMS、固定種子,同 v1
- 3 段 × 4 條件 = 12 檔

### 1.6 實驗 arm

| arm | 聽 | 詞表 | 語言模式 |
|---|---|---|---|
| X_cmn | SM 即時 | 無 | cmn 單語 |
| X_bi | SM 即時 | 無 | **cmn_en 中英雙語 pack** |
| Xdom_bi | SM 即時 | domain | cmn_en |
| Xsli_bi | SM 即時 | slides | cmn_en |
| Xsli_cmn | SM 即時 | slides | cmn(測詞表能否救單語模式) |
| G | Gemini Live 一路(3.1-flash-live) | — | — |

**記錄在案的替代**:handoff-v2 指定 `language: multi`;本帳號的即時 multi 模型
(melia-1)回覆 "currently not supported"。Speechmatics 另有**專用中英雙語 pack
`cmn_en`**,且支援 enhanced/max_delay/additional_vocab 全參數 —— 比 multi 更貼合
句內語碼轉換場景,故雙語 arm 使用 cmn_en。

全部即時 WS、1× 真實速度、0.5s chunk、全訊息時戳落檔。translate 層與 G 共用
kikemu 的口譯 systemInstruction(P0);P1 = P0 + 「詞表術語維持英文」規則。

## 2. 結果

### 2.1 英文術語召回率矩陣(tolerant;86 個實例 micro-average)(Q1)

| arm | M0 | M1 | M2 | M3 |
|---|---|---|---|---|
| X_cmn(單語,無詞表) | 0.521 | 0.573 | 0.563 | 0.469 |
| Xsli_cmn(單語+投影片詞表) | 0.583 | 0.667 | 0.563 | 0.542 |
| X_bi(雙語,無詞表) | 0.813 | 0.812 | 0.792 | 0.563 |
| Xdom_bi(雙語+領域詞表) | 0.802 | 0.812 | 0.812 | 0.583 |
| **Xsli_bi(雙語+投影片詞表)** | **0.833** | **0.844** | **0.865** | **0.594** |
| G(Gemini Live 一體式) | 0.927 | 0.802 | 0.792 | 0.396 |

### 2.2 核心差值(segment-cluster bootstrap 95% CI)(Q2, Q3, Q4)

| 條件 | 雙語pack−單語(Q4) | 領域詞表−無(Q3) | **投影片−領域(Q2 核心)** | 單語+投影片−單語 |
|---|---|---|---|---|
| M0 | **+0.292** [+0.125, +0.429] | −0.010 [−0.017, 0.000] | +0.031 [0.000, +0.051] | +0.062 [−0.095, +0.119] |
| M1 | **+0.240** [+0.062, +0.305] | 0.000 [0.000, 0.000] | +0.031 [0.000, +0.062] | +0.094 [0.000, +0.136] |
| M2 | **+0.229** [+0.062, +0.286] | +0.021 [0.000, +0.034] | +0.052 [0.000, +0.068] | 0.000 [−0.333, +0.102] |
| M3 | +0.094 [−0.017, +0.286] | +0.021 [0.000, +0.034] | +0.010 [−0.048, +0.034] | +0.073 [0.000, +0.102] |

**判讀:**
- **Q4(單語 vs 雙語)**:+0.23~+0.29,全實驗最大效果,M0~M2 的 CI 都排除 0
- **Q3(領域包單獨的價值)**:≈ 0。通用 ML 術語雙語 pack 本來就認識,
  645 條 Google glossary 詞表疊上去沒有增量
- **Q2(會前準備的價值)**:+0.03~+0.05,CI 下緣貼 0 —— 正向但小。
  投影片詞表救回的是 saw、sentiment analysis 這類上下文特定詞
- 詞表無法替代語言模式:cmn+投影片詞表最多 +0.09,不到換 pack 效果的一半

### 2.3 失敗模式分佈(Q5)

全 arm、全條件加總(F1 諧音中文化 / F2 誤認他字 / F4 遺漏;F3 全語言崩潰 0 件):

| arm | F1 | F2 | F4 |
|---|---|---|---|
| X_cmn | 21 | **151** | 8 |
| X_bi | 22 | 57 | 19 |
| Xsli_bi | 20 | 45 | 18 |
| G | 37 | 43 | 24 |

**問題出在「聽錯成別的英文」(F2),不是預期的「英文中文化」(F1)。**
單語模式的 F2(151)是雙語的 2.6 倍 —— cmn pack 不是把英文變中文,
而是把英文變成錯的英文(CoffeeNight、news)。這解釋了為什麼詞表救不動:
additional_vocab 提示的是「這些詞可能出現」,但單語 pack 的英文聲學模型
底子太弱,提示無法補償。F3(整段語言判定崩潰)一件都沒有發生。

### 2.4 過度翻譯(Q6)

以「ASR 已聽對的術語,譯文卻翻成中文」計(P0 = kikemu 原版;P1 = 加不譯規則):

| arm | 不該翻 P0 | 不該翻 P1 | 可翻可不翻 P0 | 可翻可不翻 P1 |
|---|---|---|---|---|
| X_cmn | 0% (0/7) | 0% | 21% | 17% |
| X_bi | **0% (0/15)** | 0% | 11% | 22% |
| Xdom_bi | 0% (0/15) | 0% | 18% | 32% |
| Xsli_bi | 17% (4/23)* | 17%* | 15% | 17% |
| Xsli_cmn | 0% (0/15) | 0% | 14% | 8% |

\* Xsli_bi 的 4/23 全部是 covid-19 被譯文寫成「新冠」—— P1 同樣沒接住,
且此詞在導覽語境譯成中文其實更自然,是分類邊界個案而非規則失效。

**P1 − P0 = 0(對關鍵類別,所有 arm)。** kikemu 原版 systemInstruction 的
「專有名詞保留原文」已把 Transformer/GAN/ChatGPT 類 100% 保住;
P1 的顯式清單規則沒有增量,一般技術詞上方向甚至不穩定(11↔22%、18↔32%,
小樣本波動)。**「不譯規則」在這條線是免費但多餘的;
廠區線的料號/機台型號應優先靠 prompt 的通則,不必維護不譯清單。**

### 2.5 一體式 G 的噪音行為(Q7)

- 乾淨(M0):0.927,**全場最強**,TER 0.069 也最低 —— 錄影音軌/會議系統
  輸出這種 line-in 級音源,一體式模型是可行選項(與 v1 結論一致)
- 殘響(M1)/辦公室(M2):0.80 上下,與 X_bi 打平
- **會議交談(M3, 12dB):0.396、TER 0.833 —— 崩潰模式重演**。
  v1 在 8dB 食堂人聲全滅、這裡 12dB 會議交談半滅,劑量反應一致:
  **人聲背景是一體式模型的斷崖**,且比 v1 更早開始(12dB 已不可用)

### 2.6 延遲(Q6 附帶)

| 指標 | X_cmn | X_bi | Xsli_bi |
|---|---|---|---|
| partial p50 | 0.80s | 0.83s | 0.81s |
| final p50 | 2.29s | 2.31s | 2.30s |

雙語 pack 與詞表對延遲皆零影響(與 v1 的詞表結論一致)。

### 2.7 成本

- Speechmatics:60 個即時 run × 5 分鐘 = 5 小時,帳面 ~$1.2,落在贈送額度
- Gemini(參考轉寫 ×6、詞表生成、P0/P1 翻譯 ×~120、G ×12):< $2
- 總計 < $4;主要成本是真實速度推流的 wall-clock(~4 小時)

### 2.8 一句話建議(Q8)

**廠區/會議線:Speechmatics `cmn_en` 雙語 pack + kikemu 原版翻譯 prompt
是基本盤(0.79~0.81 召回、partial 0.8 秒);有投影片/文件就自動生成詞表
再加 +3~5pp;會議室有多人交談(SNR ≤ 12dB)時禁用一體式模型 ——
它只在 line-in 級音源(錄影、會議系統直出)有優勢。**

### 2.9 與 v1 的合并判讀(對 stt-matrix 的更新)

| | v1 日文導覽(專名) | v2 中英夾雜演講(術語) |
|---|---|---|
| 詞表價值 | **+0.12~0.19(核心資產)** | +0.03~0.05(小加分) |
| 語言 pack | 單語即可 | **雙語 pack 是勝負手(+0.23~0.29)** |
| 一體式崩潰點 | 8dB 人聲全滅 | 12dB 人聲半滅 |
| 不譯/在地化規則 | prompt 已解決 | prompt 已解決 |

**詞表投資的判準:目標詞彙是「引擎沒見過的」(在地專名、料號)才值得;
「引擎見過但模式不對」(通用英文術語)要先修語言模式。**

## 3. 侷限

1. 音訊經公開鏡像取得(官方 YouTube 對資料中心 IP 擋下載);時長逐檔核對一致
2. 參考文本的英文拼寫仲裁依賴投影片與雙 Gemini 一致性,無人耳終審;
   函式/function 一類的系統性裁決已個別記錄證據
3. 三段語料、86 個術語實例 —— 段落層級統計力有限,CI 以術語實例 cluster 處理
4. G 的日文… 中文聽寫是 Live API 附屬輸出(inputTranscription),與 v1 同一侷限
5. cmn_en 替代 multi:結論適用於「有專用雙語 pack」的引擎;泛多語 pack 未測
6. 譯文層 P0/P1 只在 X 系列測(G 是一體式,無法拆層)
